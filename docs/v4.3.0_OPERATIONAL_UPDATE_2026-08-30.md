# ATACseq2tracks v4.3.0 operational update

## Scope

This release changes how v4.2.0 is launched, validated, audited, resumed,
reported and deployed. It deliberately does not change alignment, filtering,
normalization, peak calling, annotation, QC calculations, DiffBind,
DESeq2ATAC, spike-in formulas or default coverage families.

## Added capabilities

- activation-free `atacseq2tracks --config ...` shared command;
- literal-only configuration parser; the user file is never sourced;
- `--plan` and `--preflight-only` modes;
- named `--from-stage` and `--stop-after` boundaries;
- signatures incorporating inputs, resolved settings and implementation files;
- persistent technical-replicate, resource, software, reference and event tables;
- report-only regeneration utility;
- cleanup manifest recording every removed path and its size;
- root-owned versioned installation with atomic stable-link promotion;
- focused operational regression tests and user/administrator documentation.

## Compatibility

The 17-column core samplesheet and optional dm6 columns are unchanged.
Technical-replicate behavior is unchanged. Existing v4.2.0 full configuration
files remain valid when they use only documented keys and literal values.
Previously tolerated shell commands or custom unknown variables are now rejected
by design.

The stronger signature intentionally does not trust v4.2.0 checkpoints after a
workflow-code change. Existing completed outputs remain valid, and reports may
be regenerated independently, but a new v4.3.0 analysis should use a new output
directory or rerun from inputs.

## Validation

Run:

```bash
bash tests/check_bash_syntax.sh
atacseq2tracks --config /path/to/config.conf --plan
atacseq2tracks --config /path/to/config.conf --preflight-only
```

Before biological production, execute representative small PE and SE runs and
confirm technical merge metadata, checkpoint JSON, event timing, cleanup
manifest, report regeneration and all inherited v4.2.0 acceptance checks.
