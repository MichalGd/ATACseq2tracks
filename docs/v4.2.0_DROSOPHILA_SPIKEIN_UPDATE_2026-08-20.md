# ATACseq2tracks v4.2.0 Drosophila spike-in update

## Scope

Version 4.2.0 adds one opt-in coverage family and leaves every v4.1.0 branch,
differential model, peak set and default output unchanged. The new family is
intended for ATAC-seq libraries containing a known dm6 reference added before
tagmentation. It produces stringent host-genome bigWig and bedGraph tracks plus
the counts, scale factors, warnings and provenance needed to audit them.

The module is disabled by default:

```bash
GENERATE_DROSOPHILA_SPIKEIN_STRINGENT_TRACKS=false
```

It runs only when the switch is `true` and at least one biological sample
declares valid dm6 metadata. Only declared sample keys receive spike-in tracks;
undeclared samples continue through all inherited workflow branches unchanged.

## Why this is separate from DESeq2 normalization

The implemented track is calibrated directly from raw stringent host coverage.
It is not the existing `DESeq2RobustCPM_Stringent` track multiplied by another
factor. That distinction avoids removing library depth through DESeq2 and then
again through the external reference.

For sample `j`, let:

- `D_j` be the retained dm6 fragment count for PE or read count for SE;
- `R_j` be the declared dm6:host amount added before tagmentation;
- `T` be `SPIKEIN_SCALE_TARGET`, one million by default;
- `H_j(x)` be unnormalised stringent host coverage at genomic position `x`.

The track is:

```text
scale_j = T × R_j / D_j
SpikeInSignal_j(x) = H_j(x) × scale_j
```

When all samples received the same dm6:host amount, use `R_j=1` for each sample.
If intentionally different amounts were used, `R_j` must be the documented
relative amount, measured on the same basis for every sample. The output unit is
host coverage per configured dm6 reference target, adjusted for declared input
ratio. It is not CPM and is not an absolute molecule count.

## Competitive alignment and filtering

Trimmed FASTQs are aligned once to a concatenated host+dm6 Bowtie2 index. This
lets homologous host/fly sequences compete in the same alignment rather than
being accepted independently by two separate alignments. The reference utility
reconstructs the configured host FASTA from its Bowtie2 index and prefixes fly
contigs with `dm6__`, preventing chromosome-name collisions.

The composite BAM is coordinate-sorted and Picard duplicates are removed before
species splitting. The stringent selection is:

| Layout | samtools selection | Coverage/count unit |
|---|---|---|
| PE | `-q 30 -f 2 -F 3852`; canonical species contigs; blacklist filtering; pairs repaired and re-required | one properly paired first mate (`-f 66`) per fragment; coverage extended across the insert |
| SE | `-q 30 -F 3844`; canonical species contigs; blacklist filtering | one retained primary read; no artificial extension |

Flags 3852/3844 exclude unmapped, secondary, QC-failed, duplicate and
supplementary records; PE additionally excludes mate-unmapped records and
requires a proper pair. Bowtie2 emits one primary alignment for a multimapping
observation, but `MAPQ>=30` removes ambiguous alignments under Bowtie2's scoring
model. MAPQ is an ambiguity proxy, not proof of unique biological origin.

Host canonical chromosomes follow the existing hg38/mm39 autosome+X/Y policy.
The dm6 default is `2L,2R,3L,3R,4,X`. Mitochondrial and noncanonical sequences
do not contribute to either denominator or final coverage. Both species use
their configured blacklist.

## Inputs

Add all three optional columns to a spike-in samplesheet:

| Column | Allowed value/meaning |
|---|---|
| `spikein_genome` | `dm6` for a declared reference; blank when unused |
| `spikein_to_host_ratio` | Positive relative amount added on a consistent basis; use `1` if equal across the cohort |
| `spikein_stage` | `pre_tagmentation_nuclei` |

Technical-replicate rows for one `sample_id + replicate` must agree. Existing
17-column samplesheets remain valid while spike-in mode is disabled. Use
`config/samplesheet_example_atac_spikein.csv` as the template.

Required configuration paths are:

```bash
INDEX_HG38_DM6="/opt/bioinformatics/references/composite/hg38_dm6/bowtie2/hg38_dm6"
INDEX_MM39_DM6="/opt/bioinformatics/references/composite/mm39_dm6/bowtie2/mm39_dm6"
CHROM_SIZES_DM6="/opt/bioinformatics/references/dm6/dm6.chrom.sizes"
BLACKLIST_DM6="/opt/bioinformatics/references/dm6/dm6-blacklist.v2.bed"
```

Build and install a composite for each enabled host with:

```bash
bash utilities/prepare_dm6_spikein_references.sh \
  hg38 /absolute/shared/path/to/hg38/index \
  /absolute/shared/path/to/dm6.fa.gz \
  /absolute/shared/path/to/dm6.chrom.sizes \
  /absolute/shared/path/to/dm6-blacklist.v2.bed \
  /opt/bioinformatics/references
```

Repeat with `mm39` and its host index. The utility requires all six source index
components, validates inputs, copies rather than moves source data, and writes a
SHA-256 `reference_manifest.tsv`.

## Outputs and QC

Final tracks:

```text
bigwig_spikein/stringent/<KEY>_SpikeInDM6_Stringent.bw
bigwig_spikein/stringent/<KEY>_SpikeInDM6_Stringent.bedGraph
```

Audit tables:

```text
spikein/tables/spikein_normalization.tsv
spikein/tables/spikein_warnings.tsv
spikein/tables/spikein_provenance.tsv
```

The normalization table records host/dm6 retained counts, dm6 fraction,
composite primary observations before/after MAPQ filtering, the low-MAPQ
ambiguity proxy, duplicate percentage when available, declared ratio, target,
applied scale, index checksum and blacklist checksums.

Defaults hard-fail below 1,000 retained dm6 observations and warn below 10,000.
Fractions below 0.1% or above 20% warn. These are conservative operational
defaults, not universal assay standards; change them only with documented
validation. A hard failure prevents a misleading extreme scale factor.

## Checkpoints, cleanup and compatibility

The module uses checkpoint `step6s.done`. A failed child sample fails the stage;
the checkpoint is not written. Completed per-sample files are reused safely.
Because checkpoints include the workflow version/config signature, moving an
old run to v4.2.0 invalidates old signatures rather than silently mixing code.

`KEEP_SPIKEIN_BAMS=false` deletes composite, deduplicated and species-split BAMs
only after the complete workflow succeeds. Tracks, metadata and logs remain.
Set it to `true` during initial server validation. PE and SE are supported in
separate runs; mixed-layout cohorts remain rejected.

## Interpretation limits

- Spike-in calibration can preserve a genuine global host-accessibility shift
  that DESeq2's majority-stable assumption may remove.
- It does not repair unequal spike-in addition, incorrect cell/nuclei counts,
  variable species lysis, or a reference added after the technical step of
  interest.
- It does not correct protocol, laboratory, genome-build or other batch effects.
- Cross-study comparisons require the same spike-in organism/build, addition
  stage and ratio definition, composite-reference construction, alignment and
  filtering, signal unit and scale target. Even then, interpretation remains
  relative to recovery of the external reference.
- Samples without a declared/adequate dm6 reference cannot receive this track;
  controls may receive it when they contain the same reference and declare it.

## Required validation before production use

1. Run `bash tests/check_bash_syntax.sh` on Linux.
2. Run small PE and SE datasets and verify non-empty tracks, table arithmetic,
   canonical chromosomes, pair/read counting and cleanup/resume behavior.
3. Downsample the same composite BAM to several depths. Retained dm6 counts and
   raw host coverage should fall together, while calibrated signal over stable
   host regions remains approximately constant within sampling error.
4. Create or identify libraries with known host:dm6 mixtures and confirm that
   scales change inversely with recovered dm6 after ratio adjustment.
5. Compare dm6 counts/fractions, scale factors, FRiP, replicate correlations,
   invariant-region signal and expected global biological shifts.
6. Inspect cross-species ambiguity using the reported low-MAPQ primary count and
   repeat representative alignments against the exact production composite.
