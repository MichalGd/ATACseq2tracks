# ATACseq2tracks v4.1.0 filtering-policy coverage update

**Release date:** 20 August 2026  
**Scope:** Coverage generation and normalization sensitivity only. Alignment,
peak calling, QC, annotation and differential-accessibility models retain their
v4.0.0 behavior.

## What changed

Five coverage families are enabled by default:

CPM follows the existing per-sample behavior. DESeq2-derived cohorts and their
policy-specific tracks include non-control biological sample keys, consistent
with the existing consensus normalization module.

| Family | BAM policy | Outputs |
|---|---|---|
| CPM | Picard deduplicated, current `MIN_MAPQ=30` filtering | `*_CPM.{bw,bedGraph}` |
| DESeq2Consensus | Same current filtered BAM | `*_DESeq2Consensus.{bw,bedGraph}` |
| Robust permissive | Pre-dedup BAM, primary records, MAPQ 0 | `*_DESeq2RobustCPM_Permissive.{bw,bedGraph}` |
| Robust intermediate | Picard-deduplicated BAM, primary records, MAPQ 0 | `*_DESeq2RobustCPM_Intermediate.{bw,bedGraph}` |
| Robust stringent | Current deduplicated, `MIN_MAPQ=30` BAM | `*_DESeq2RobustCPM_Stringent.{bw,bedGraph}` |

The legacy `*_DESeq2RobustCPM.{bw,bedGraph}` output remains as an identical
stringent compatibility copy for one release line.

All branches remove secondary and supplementary alignments, apply the same
blacklist and canonical autosome/X/Y universe, and count paired-end fragments
once. Single-end data retain one read per observation.

Bowtie2 remains in default one-primary-alignment reporting mode. MAPQ 0 tracks
therefore retain one selected primary placement from ambiguous reads; they do
not retain every possible placement. Equal-scoring placements can be selected
pseudo-randomly but reproducibly. The stringent MAPQ 30 branch excludes most
ambiguous alignments but is described as high-confidence, not mathematically
unique.

## Fixed peak universe and policy-specific factors

The v4.0.0 production peak calls and Step 10 consensus BED define one fixed
genomic universe for every robust policy. Recalling peaks for each policy would
confound the filtering comparison with changes in interval definition.

For policy `p`, the workflow counts its retained fragments/reads over the fixed
BED to obtain `K_p`, estimates separate DESeq2 `poscounts` size factors `s_pj`,
and calculates:

```text
G_p = exp(mean(log(colSums(K_p))))
scale_pj = 1e6 / (s_pj * G_p)
```

Thus each policy has an internally consistent count matrix, factors and robust
cohort constant. Absolute amplitudes should not be compared naively between
policies because their observed libraries and cohort constants differ.

## Configuration

```bash
GENERATE_CPM_TRACKS=true
GENERATE_DESEQ2_CONSENSUS_TRACKS=true
GENERATE_DESEQ2_ROBUST_CPM_PERMISSIVE_TRACKS=true
GENERATE_DESEQ2_ROBUST_CPM_INTERMEDIATE_TRACKS=true
GENERATE_DESEQ2_ROBUST_CPM_STRINGENT_TRACKS=true

GENERATE_COVERAGE_BIGWIGS=true
GENERATE_COVERAGE_BEDGRAPHS=true

PERMISSIVE_MIN_MAPQ=0
INTERMEDIATE_MIN_MAPQ=0
COVERAGE_FILTER_PARALLEL_JOBS=2
KEEP_NORMALIZATION_POLICY_BAMS=false
```

Setting a family switch to `false` prevents its track generation. Disabling a
permissive or intermediate family also prevents creation of that temporary BAM
branch. The two format switches apply to every enabled family; preflight rejects
an enabled coverage family when both formats are disabled.

Switches do not delete files produced by an earlier run in the same output
directory. Archive or explicitly remove stale tracks before using file presence
as evidence of what a newly configured run generated.

## Outputs and metadata

Policy matrices, factor tables and metadata are written below:

```text
coverage_filtering_sensitivity/
├── track_normalization_metadata.tsv
├── permissive/
│   ├── matrices/
│   └── tables/
└── intermediate/
    ├── matrices/
    └── tables/
```

Metadata records source BAM stage, duplicate policy, Bowtie2 reporting mode,
MAPQ threshold, PE/SE signal unit, retained observations, MAPQ bins, `XS`-tagged
observations, the consensus BED checksum, column sum, size factor, consensus
scale and robust-CPM scale.

The default cleanup removes temporary BAMs in
`coverage_filtering_policy_bams/` only after complete workflow success. Set
`KEEP_NORMALIZATION_POLICY_BAMS=true` to retain them. A failed workflow retains
the BAMs for diagnosis.

## Checkpoints and existing runs

Step `10b` independently checkpoints permissive/intermediate filtering and
track generation. A v4.1.0 version/config signature differs from v4.0.0, so
launching the complete v4.1.0 entry point in an old output directory does not
silently trust v4.0.0 checkpoints.

The new sensitivity branches require pre-dedup `bams/` and, for intermediate,
`dedupBams/`. If an older successful run already removed these through cleanup,
the additional policies require re-alignment/deduplication. Existing filtered
BAMs alone cannot reconstruct removed duplicates or low-MAPQ records.

## Interpretation

- CPM, DESeq2Consensus and stringent robust CPM remain the main production
  visualization families.
- Permissive versus intermediate primarily measures the effect of Picard
  duplicate removal at MAPQ 0.
- Intermediate versus stringent primarily measures the effect of MAPQ 30.
- Duplicate-retained tracks may reflect PCR amplification.
- Low-MAPQ tracks may place repeat-derived signal at an arbitrary selected
  primary locus.
- Probabilistic or fractional multimapper assignment is not implemented.

These sensitivity tracks do not alter DiffBind or DESeq2ATAC inputs.

## Required validation before shared production use

Run `bash tests/check_bash_syntax.sh`, then test representative PE and SE
datasets. Confirm non-empty enabled files, one-fragment PE counting, canonical
chromosomes only, identical consensus checksums, separate policy factors,
expected `permissive >= intermediate >= stringent` retained observations, UCSC
track files, checkpoint resume and success-only cleanup.
