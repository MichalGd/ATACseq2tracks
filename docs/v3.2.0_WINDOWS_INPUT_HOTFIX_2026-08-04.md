# ATACseq2tracks v3.2.0 Windows-input hotfix — 2026-08-04

## Purpose

This cumulative v3.2.0 hotfix prevents Windows/Excel text encoding artifacts
from stopping the workflow before preflight. The workflow version remains
**3.2.0**; `VERSION`, `environment.yml`, and site-specific configuration files
are not included in the overlay.

## Automatic behavior

Both `smoke_test.sh` and the main entry point inspect the configuration before
Bash sources it. After loading the corrected configuration, the main workflow
also inspects the configured samplesheet. Preflight inspects the samplesheet
argument in the same way.

The sanitizer recognizes:

- CRLF (`\r\n`) line endings;
- bare carriage-return (`\r`) line endings;
- UTF-8 BOM;
- BOM-marked UTF-16 and UTF-32 text;
- a trailing DOS EOF marker (Ctrl-Z).

When any of these are found, it:

1. resolves the real input file;
2. creates a byte-for-byte backup in the same directory;
3. converts the input to UTF-8 with LF line endings;
4. preserves its file permissions;
5. atomically replaces the affected input;
6. continues using the corrected file.

Example messages:

```text
[INPUT] Corrected: /project/config/config.conf
[INPUT] Artifacts: UTF-8 BOM, CRLF line endings
[INPUT] Original backup: /project/config/config.conf.windows-artifact-backup.20260804T120000.000000Z.12345
```

Clean UTF-8/LF files are not rewritten:

```text
[INPUT] OK: /project/config/samplesheet.csv (UTF-8/LF; unchanged)
```

Unknown encodings without a recognized BOM are not guessed. Preflight stops
without modifying the original. Backups preserve the original permissions and
may contain the same sensitive paths or settings as the configuration; keep
them protected.

## Install the cumulative overlay

The archive contains the earlier v3.2.0 test-run corrections as well as this
Windows-input protection. Run from the parent of the installed workflow:

```bash
cd /home/micgdu/Analysis/workflows

tar -xzf ATACseq2tracks_v3.2.0_cumulative_hotfix_2026-08-04_overlay.tar.gz

cd ATACseq2tracks
bash tests/check_bash_syntax.sh
```

Expected new test output includes:

```text
OK   scripts/sanitize_text_inputs.py
OK   Windows artifacts are backed up and normalized
OK   clean inputs are unchanged and normalization is idempotent
OK   unknown encodings are rejected without modification
OK   Windows input sanitizer regression checks
```

## Run project preflight

Keep the main environment's Python first and append the separate ataqv tools:

```bash
conda activate ATACseq2tracks
export PATH="$CONDA_PREFIX/bin:$PATH:$HOME/.conda/envs/ataqv-tools/bin"
hash -r

cd /home/micgdu/Analysis/run7_ATAC

bash /home/micgdu/Analysis/workflows/ATACseq2tracks/scripts/smoke_test.sh \
  config/samplesheet.csv config/config.conf
```

The current files should report `UTF-8/LF; unchanged`. If a future Windows
copy introduces artifacts, preflight will show the correction and backup path,
then continue validating the corrected files.

## Find or restore backups

List backups:

```bash
find /home/micgdu/Analysis/run7_ATAC/config -maxdepth 1 \
  -name '*.windows-artifact-backup.*' -print
```

To restore one, first stop the workflow, inspect the exact backup name, and
copy that backup over its corresponding input. Restoration is deliberately not
automatic because it would restore the Windows artifacts as well.

## Manual use

The same safe normalization can be applied to another configuration or CSV:

```bash
python3 /home/micgdu/Analysis/workflows/ATACseq2tracks/scripts/sanitize_text_inputs.py \
  /absolute/path/to/config.conf /absolute/path/to/samplesheet.csv
```
