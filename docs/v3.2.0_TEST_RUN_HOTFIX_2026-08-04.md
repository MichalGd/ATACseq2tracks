# ATACseq2tracks v3.2.0 test-run hotfix — 2026-08-04

> **Historical hotfix record:** Current track names, cleanup defaults,
> differential behavior and deployment guidance are documented in the
> [main README](../README.md) and [current update](v3.2.0_UNIVERSAL_DIFFERENTIAL_ANNOTATION_UPDATE_2026-08-18.md).

## Decision

Keep the workflow version at **3.2.0** until the end-to-end server test has
completed and any further integration defects have been corrected. Do not tag
or publish v3.2.1 for this hotfix.

The hotfix overlay intentionally does not contain `VERSION`, `environment.yml`,
or `config/config.conf`. Applying it therefore preserves the v3.2.0 checkpoint
signature and all site-specific server paths.

## What the test run proved

The attached run completed Steps 1–9. Step 10 completed its expensive QC and
DESeq2 size-factor calculation, then stopped before generating the first
DESeq2-consensus bigWig:

```text
Invalid size factor for AT_BasPMK_r1_S31_bioR1: mm39
```

The size-factor table is valid. Its columns are `sample_id`, `key`, `genome`,
`size_factor`, `track_scale_factor`, and `basis`; the old shell code selected
field 3 (`genome`) instead of the named `size_factor` field.

The same run exposed two other confirmed defects:

- Picard duplication percentages were reported as values such as
  `230046800.00%` because whitespace parsing shifted the empty `LIBRARY` field
  and selected `ESTIMATED_LIBRARY_SIZE`.
- Step 5 MultiQC searched only `dedupBams/`, while Picard metrics are written to
  `logs/picard/`; consequently it reported no analysis results.

The audit of the not-yet-executed stages also corrected DiffBind handling of
broadPeak files and header-only companion sample sheets. DiffBind accepts
`narrow` and generic `bed` peak callers, but not a `broad` identifier.

## Resume this test run

Remove Step 5's checkpoint only to regenerate its corrected Picard MultiQC
report. Step 10 did not create a successful checkpoint, but removing it
explicitly is harmless and guarantees that the fixed stage is used.

```bash
cd /home/micgdu/Analysis/run7_ATAC
rm -f atacseq2tracks/.checkpoints/step5.done \
      atacseq2tracks/.checkpoints/step10.done

conda activate ATACseq2tracks
export PATH="$HOME/.conda/envs/ataqv-tools/bin:$PATH"

nohup bash /home/micgdu/Analysis/workflows/ATACseq2tracks/atacseq2tracks.sh \
  --config /home/micgdu/Analysis/run7_ATAC/config/config.conf \
  > atacseq2tracks_v3.2.0_hotfix_resume.log 2>&1 &

echo $! > atacseq2tracks_v3.2.0_hotfix_resume.pid
tail -f atacseq2tracks_v3.2.0_hotfix_resume.log
```

Steps 1–4 and 6–9 should be skipped by their unchanged v3.2.0 signatures.
Step 5 should skip existing BAM processing and regenerate MultiQC. Step 10 and
then Steps 11–14 should run. Automatic cleanup occurs only after Step 14
succeeds, according to the existing project configuration.

## Expected corrected evidence

- `qc_post_alignment/tables/qc_summary.tsv` contains plausible duplication
  percentages in the 0–100 range.
- `qc_post_alignment/tables/consensus_sizeFactors.tsv` retains numeric,
  positive factors.
- `bigwig_deseq2_consensus/` contains one non-empty
  `*_DESeq2Consensus.bw` per biological sample.
- `qc_post_alignment/atac_qc/` contains TSS-enrichment metrics, fragment
  periodicity tables/plots, and compressed ataqv JSON.
- `diffbind_results/` contains separate runnable narrow and broad analyses (or
  a clear warning if one peak type legitimately has no valid samples), with
  `diffbind_results_all_sites.csv` and the FDR 0.05 `diffbind_results.csv`.
- `bigwig*/ucsc_tracks.txt` files describe the RPM, DESeq2-consensus, and merged
  browser tracks.
- `.checkpoints/step10.done` through `.checkpoints/step14.done` exist only after
  their respective stages succeed.

## Deferred observations

The MultiQC messages about values such as `77,175,74` not being `#RRGGBB`
were non-fatal and appear to come from an external/user MultiQC colour
configuration, not the workflow's UCSC track file. They are not changed by
this hotfix. If they persist, inspect the server's MultiQC configuration after
the workflow completes.

This package has shell syntax and focused parser regression coverage locally.
The server resume is the required integration test for BAM/deepTools/ataqv and
the installed DiffBind 3.16 environment.
