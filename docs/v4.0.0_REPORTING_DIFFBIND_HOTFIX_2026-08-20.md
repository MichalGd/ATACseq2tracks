# ATACseq2tracks v4.0.0 reporting and DiffBind hotfix

Date: 2026-08-20

## Scope

This hotfix addresses two warnings observed in the completed four-condition
paired-end production run. It does not change alignment, fragment counting,
track normalization, peak-calling parameters, differential model design,
contrast direction, output names or checkpoint numbers.

## DiffBind genomic-universe correction

Previously, DiffBind received the original MACS3 peak files for its first
all-sample count and the resulting consensus was canonical/blacklist-filtered
afterward. This produced Seqinfo warnings when sample peak files contained
different alternate contigs. The final model already recounted on a canonical,
blacklist-filtered consensus, so the completed run does not require reanalysis.

The hotfix now applies the same policy before the first DiffBind operation:

1. read every original broad/narrow peak file without changing its columns;
2. retain canonical autosomes and X/Y for the configured hg38/mm39 build;
3. remove every interval overlapping the configured blacklist;
4. write the filtered input and a per-sample audit manifest;
5. use the filtered samplesheet for both all-sample consensus creation and the
   eligible-condition recount.

New outputs in each broad/narrow DiffBind result directory are:

```text
diffbind_peak_prefilter_manifest.tsv
diffbind_samplesheet_prefiltered.csv
prefiltered_peaks/
```

The wrapper validates these files before accepting the analysis.

## MultiQC reporting correction

MultiQC 1.35 caught a deepTools-module validation error while parsing
`plotPCA` auxiliary TSV files, replaced duplicate sample IDs from multiple
plotPCA/plotCorrelation datasets and rejected RGB-triplet colour strings. It
still returned success, causing Step 14 to checkpoint a partial report.

The hotfix retains every authoritative deepTools table and standalone plot but
excludes the incompatible native MultiQC deepTools parser. Eight available
deepTools PNGs are staged temporarily with `_mqc.png` names and embedded as
self-contained custom-content sections. This follows MultiQC's documented
custom-image convention:

https://docs.seqera.io/multiqc/custom_content#images

The report wrapper now captures the MultiQC console log and exits non-zero if
MultiQC reports a caught module failure, validation error or colour-conversion
error, or if the expected HTML and differential summary files are empty.

## Warnings intentionally unchanged

- A recovered BiocParallel port retry does not affect results.
- Fontconfig initialization warnings do not affect plots when text renders.

These messages do not justify workflow-level workarounds.

## Validation

Run:

```bash
bash tests/check_bash_syntax.sh
```

`tests/test_reporting_diffbind_hotfix.sh` checks pre-count filtering contracts,
mocked MultiQC custom-image staging, native deepTools exclusion, report output
validation and propagation of a caught MultiQC module failure.
